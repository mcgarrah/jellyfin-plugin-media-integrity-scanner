Scanning Behavior

Number of files scanned simultaneously. Defaults to half this host's vCPU count on a fresh install; once saved (including if left at that default), this value sticks across restarts and upgrades rather than being recomputed.
Minimum pause before each file, regardless of file size.
Only affects Phase 2 (deep scan) decoding -- Phase 1's header check uses ffprobe, which never decodes the file. Requires the corresponding GPU to actually be passed through to this Jellyfin instance with its driver installed; not yet verified against real hardware in this deployment, including whether ffmpeg falls back to software cleanly or errors out if the device isn't actually available -- test against a single file before relying on it for a full library scan. Every scan result records which mode (software/hardware, and which backend) actually decoded it, so results from before and after enabling this stay distinguishable.
Triggers an immediate Header-phase rescan when a file is replaced (same item, different bytes) -- independent of "Scan newly added items" above. Even with this off, a changed file still gets caught on the next scheduled sweep via its changed modification time; this only controls whether it happens right away.

I/O Throttling

Shared aggregate cap across all concurrent scans (Header and Deep alike), not a per-file limit -- running more scans at once divides this budget rather than multiplying total throughput past it. Deep scans get priority over Header scans when both are contending for it. 0 disables throttling.
A start time later than the end time wraps past midnight.

FFmpeg Paths

Only needed if the plugin picks the wrong ffmpeg/ffprobe binary automatically. When both overrides above are set, Jellyfin's own global ffmpeg path (Dashboard > Playback > Transcoding) is never consulted for either binary.

The resolved ffmpeg/ffprobe paths are otherwise only re-checked on restart/upgrade, or automatically when Jellyfin's own settings are saved (skipped if both overrides above are set, since there would be nothing to invalidate). Use this button to force a re-check immediately without saving this form or restarting.

Update Checking

Only versions from a repository you've registered under Dashboard > Plugins > Repositories can ever be detected -- each manifest URL below needs its own separate entry there (Add > paste the URL > Save) before its channel will find anything.
Only used if the Development channel is selected above -- and only works once this exact URL is also registered as its own repository under Dashboard > Plugins > Repositories. Registering the Stable Manifest URL there does not make Jellyfin aware of development builds too; switching the channel above without this extra step will silently never find an update.
Off by default. Installing an update never takes effect until Jellyfin restarts -- with automatic restart left off, an installed update just waits for you to restart manually whenever's convenient, same as clicking "Update Now" on the dashboard yourself.

Database Maintenance

On by default. Runs an integrity check against this plugin's own scan-history database, then a VACUUM if it passes, on a weekly schedule -- always skipped automatically while a scan is in progress. Also available as a manual "Run Maintenance Now" button on the dashboard.
On by default. Purges scan-history rows for items no longer in the library -- the periodic counterpart to "Purge scan records when items are removed" above, catching anything that event-driven purge missed (plugin offline at removal time, that setting was off, etc.). Runs weekly, Sunday 2:30 AM by default (retarget via Dashboard > Scheduled Tasks); always skipped automatically while a scan is in progress, regardless of this setting.

Radarr / Sonarr Integration

Lets the Media Issues page manually forward a bad movie or episode file to Radarr/Sonarr for deletion + re-download. Manual "Send" from the Media Issues page always works regardless of the automatic-forwarding settings below.

Sonarr Servers

How far back to look for the "grabbed" download record to blocklist alongside a delete. A grab older than this is assumed already-superseded -- the file is still deleted and re-searched, just without blocklisting a stale release.

Automatic Forwarding

Off by default -- this deletes real files on another system. Every automatic action is also fully logged and visible on the Media Issues page, including unmatched/skipped/dry-run outcomes, not just successes.
On by default even once forwarding is enabled above -- a deliberate two-step opt-in, so a first-time enable never immediately starts deleting files. Turn this off only once you've reviewed a few dry-run outcomes on the Media Issues page and trust the matching.
Error means the scan itself broke (ffprobe crashed, a read error) -- a weaker signal that the media is actually bad than a completed scan that affirmatively found corruption.
Bounds the blast radius of a scanner false-positive or a bad ffmpeg build flagging a large swath of the library at once. Safe to bump up temporarily during an initial full-library review and bring back down afterward.
How long to wait before automatically forwarding the same item again, even if it fails a later scan too -- default 168 (1 week). Prevents a persistently-failing item (e.g. a codec this environment's ffmpeg genuinely can't decode) from cycling right away.
After this many total automatic attempts on the same item, it's permanently blocked from further automatic forwarding and flagged in the "Needs Manual Review" banner on the Media Issues page, until reset there. A repeatedly-failing item is a strong signal the problem isn't a bad release at all.
